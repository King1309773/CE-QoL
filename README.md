# CE QoL / 便捷增强

Minecraft Forge 1.12.2 客户端模组，当前版本 1.4.0 将以下五项功能整合到一个模组入口和一个安装文件：

| 功能 | 合并来源 | 使用方式 |
|---|---|---|
| 重铸台品质显示 | Reforging Quality Display 1.2.1 | 打开 Quality Tools 重铸台，品质和效果在右侧常驻显示 |
| 可视化按键 | Visual Controls 1.1.0 | 控制设置中的可视化按键入口，或 CE QoL 配置页 |
| 温度 HUD | SD Temperature HUD 1.6.1 | 显示体温、分析、预警，配置页调整布局和外观 |
| 补水预览 | Thirst Preview 1.1.4 | 物品提示只显示整滴/半滴，手持时预览口渴条恢复 |
| 自动钓鱼 | AutoFish 1.0.4 本地 stablefix2 | 持竿按原快捷键启停，手动抛第一杆后自动收竿、再抛竿 |

补水提示没有点数、倍率、“补水：”前缀或数字回退。保留 RS 底部信息、文字列表提示、已核验 GraveStone 横条和原生水滴条的适配。

## 安装

环境为 Minecraft 1.12.2、Forge 14.23.5.2860、Java 8。保留 SimpleDifficulty 0.3.9、QualityTools 1.0.7 及它们原有的依赖。

从 CE QoL 1.1.x / 1.2.0 / 1.3.0 升级：退出游戏，备份并移出旧 CE QoL，再安装 `ceqol-1.4.0.jar`。从 1.0.0 升级时还需要移出独立的 `forgeautofish` JAR。

首次从独立版切换：将 `reforgingquality`、`visualcontrols`、`sdtemperaturehud`、`thirstpreview`、`forgeautofish` 五个 JAR 移出 `mods` 并备份，再安装合并版。不能同时保留被合并的独立版或多个 CE QoL 版本。只需客户端安装。

继续使用现有的 `config/sdtemperaturehud.cfg`、`config/thirstpreview.cfg`，无需重新设置温度布局、颜色和补水开关。按键绑定继续使用原版设置文件，包括 AutoFish 的原按键名称和绑定。模组列表中只显示一个 CE QoL 条目，点击配置可进入统一设置页。

补水设置现在先在本页编辑，点击“保存”后统一生效；“取消”和 Esc 放弃本次修改。调整窗口尺寸不会丢失未保存的选项，悬停按钮可查看说明。配置值未变时不重写文件；保存仍保留其他配置项的值。温度设置页继续使用原来的应用、完成和取消方式。

1.2.0 的补水和钓鱼设置使用临时文件写入、读回校验和旧文件 `.bak` 备份；保存失败时留在原页面、显示红色提示并保留草稿，成功后才更新实际设置。损坏配置会拒绝保存，保留原文。其他配置项的值保留，不承诺逐字保留任意原始注释。温度设置仍使用原有 Forge 保存机制。

按键搜索/筛选不再重算全部冲突，修改绑定后才刷新冲突；翻译搜索文本复用。重铸台品质文字和换行结果按物品/NBT、界面尺寸、玩家/世界、语言与字体缓存，界面切换或资源重载时清除。具体性能收益尚未进行游戏 FPS 基准测量。

1.1.1 跳过未使用的横条 HUD 的手持物品解析，并在单次选择中避免对同一物品对象重复解析。补水结果不跨帧缓存，NBT 与实际规则变化仍会被即时读取；没有额外后台线程，也不改变自动钓鱼的时序。

品质面板沿用原容器、槽位和重铸处理，不改品质概率、材料消耗或服务端规则。DebrisClient 自动重铸仍为可选适配；其开关由 DebrisClient 自身管理。

卸载时移出合并版，恢复备份的旧合并版与 AutoFish，或恢复五个独立 JAR。配置文件可保留。温度 HUD 的地图集成继续按实际安装的 Xaero 模组启用，编译依赖没有打入合并版。

## 统一 HUD 编辑与文字布局缓存

1.4.0 新入口：模组列表 → CE QoL → 配置 → 统一 HUD 布局编辑。原温度设置页的布局编辑入口也打开同一个编辑器；从统一入口可在主菜单使用示例预览。没有实时温度数据时使用示例，钓鱼状态始终使用等待咬钩的布局示例，不会启用自动钓鱼。

- 鼠标选择并拖动温度简栏、温度分析面板或钓鱼状态；白色边框表示当前选中面板。靠近屏幕边缘和中心时吸附，按住 Shift 取消吸附，拖动时显示中心辅助线。
- 滚轮只缩放选中的温度面板；钓鱼状态保持原字体大小和左侧/底部距离格式。R 或“重置选中面板”只恢复当前面板的位置/温度比例，默认值按当前窗口计算。
- 调整窗口保留草稿；点击保存才写入配置。取消、Esc、界面替换或断线放弃草稿。保存失败时保留草稿和编辑器，可重试。
- 保存捕获当时的实际设置，仅替换发生变动的面板位置和比例；其他温度外观、补水、钓鱼保护参数及快捷键保留。首次修改旧温度布局时同时转换两个面板，防止未选面板跳位。只改钓鱼位置不会转换温度布局。
- 沿用 1.3.0 的配置事务和备份；HUD 保存会成为预设页“撤销上次应用”的最近操作。原配置文件、预设格式和快捷键身份保持兼容。补水预览继续跟随原口渴条，不在自由拖动范围中。

温度简栏/分析面板和钓鱼状态的文字与尺寸采用各自单条缓存：内容、设置、语言、字体对象、Unicode/双向文字标志或资源重载变化后重新计算。温度采样频率、警告动画、钓鱼处理时序没有改动。临时温度变化提示仍按原路径生成；没有测量实际整包 FPS，不承诺帧数提升。

## 自动钓鱼

默认使用反斜杠键启停，已有自定义绑定继续沿用。统一设置页的“自动钓鱼快捷键”会直接筛选出对应按键，方便修改；它不是启动钓鱼的按钮。

新增“钓鱼状态与鱼竿保护”设置页。状态行显示等待手动首杆、等待咬钩、等待重抛、等待新鱼漂、未持竿暂停或低耐久停止；F1、菜单、创造与旁观模式隐藏状态行。可关闭状态提示，调整其左侧/底部距离；单击位置按钮增加 8 像素，Shift 单击减少 8 像素。

低耐久保护默认开启，剩余耐久不高于 10 点时停止自动操作并提醒一次；阈值可在 1～100 间调整。等待重抛期间也检查，低耐久时不会自动收竿或重抛，需要手动处理已抛出的鱼漂。保护依据物品暴露的原版耐久；不可损坏/无耐久鱼竿跳过，无法预测其他模组隐藏的额外消耗，也不限制手动操作。

以上新选项保存在 `config/ceqol.cfg` 的 `fishing` 分类，首次启动生成；原温度、补水文件和 options.txt 的按键继续沿用。钓鱼设置同样需“保存”后生效，取消/Esc 放弃草稿；开关运行状态仍由原快捷键控制。

先手动抛第一杆。只在自己的活鱼漂附近收到原版真正咬钩声后收竿，至少等待十次客户端更新并确认旧鱼漂消失，再抛一次。普通入水和鱼漂下沉不会触发；没有新鱼漂时不连续重试。

保留 stablefix2 的关闭、换物品、死亡、断线和会话变更时的清理逻辑；不使用后台延迟线程。依赖原版咬钩声音事件，替换该事件的模组仍可能影响识别。AutoFish 原作者为 NorthWestWind，本地稳定补丁及整合另行注明；来源和上游许可原文见 SOURCE_MODULES.md 与 `META-INF/licenses/autofish/`。

## 设置预设、导入导出与默认值

入口：模组列表 → CE QoL → 配置 → 设置预设与导入导出。

- 输入名称（支持中文、字母、数字、空格、下划线和连字符，最多 32 字符），选择“保存与重置范围”，把当前实际设置保存为命名预设。
- 范围可选温度 HUD、补水显示、钓鱼显示与保护或全部三项。包含温度布局/颜色/可见项目/提醒/地图显示、补水三项开关、钓鱼状态/位置/保护阈值。快捷键、钓鱼当前启停状态、玩法规则与其他模组设置不进入预设。
- 用左右按钮选择预设，点击“应用”后确认涉及的功能；应用按预设自身包含的功能生效。“保存与重置范围”只控制新建预设和恢复默认的范围，不缩减已选预设的应用范围。
- “恢复此范围默认”会先确认，只重置所选功能；“撤销上次应用”只恢复上次操作涉及的功能，不覆盖其他功能后来做的调整。撤销本身也会保留当前状态，因此可以再次撤销切换回去。
- “导出”写入 `config/ceqol/exports/<名称>.json`。分享时复制这个 JSON 文件；“打开目录”可查看预设目录及其相邻的导入、导出和备份目录。
- 把收到的 JSON 放入 `config/ceqol/imports/`，点击“选择导入文件”，选择文件并导入。同名覆盖前会显示目标名称并确认；导入仅存入本地预设列表，不会自动应用，仍需点击应用。

本地预设位于 `config/ceqol/presets/`；应用前的设置和原配置字节备份位于 `config/ceqol/preset-backups/`。格式包含版本、功能白名单和范围校验，拒绝缺失/未知键、重复 JSON 键、无效颜色/枚举、越界数值及过大的文件。每个目录最多列出 200 个 JSON；不支持自动执行脚本或从文件指定外部路径。

应用成功后写入原有三份配置，温度的 Forge 缓存也同步更新；重启沿用已应用设置，不会在启动时自动应用某个命名预设。发生可检测的写入/刷新失败会回滚已提交文件与实际字段并保留备份；多文件操作不保证断电原子性，回滚遇到外部并发改动时可能无法完整恢复，请使用备份核对。预设没有游戏每帧开销。

## 补水图标范围

2 点对应一滴，1 点对应半滴。当前目标整合包全部 133 条消费规则为 1～20 点，可完整显示；自定义绝对值超过 20 点时最多十滴，零值为空滴，负值为红色整/半轮廓。图标行无法安全容纳时跳过，不显示数字。

完全绕过 Forge 物品提示生成/绘制事件的界面、任务名称标签和流体条目仍需另行适配。联机客户端和服务端应使用相同的补水规则。

## 构建

使用 JDK 8。将构建引用放入 `libs/`：SimpleDifficulty 0.3.9、QualityTools 1.0.7、XaeroLib 1.7.3、Xaero Minimap 26.6.0、Xaero World Map 1.47.0，文件名与 `build.gradle` 一致。它们只用于编译引用，不会合入成品。

```powershell
.\gradlew.bat test build --console=plain
```

可通过 `-PpackRules=<consumableThirst.json绝对路径>` 和 `-PgravestoneJar=<GraveStone-1.0.0.jar绝对路径>` 指定目标规则与适配指纹测试。没有可选指纹文件时，不能将跳过视为已验证对应环境。

自动钓鱼的 43 项真实处理器回归单独运行 `verification/autofish/run-tests.ps1`，直接验证重混淆后的成品；边界测试桩不会进入正常 Gradle 类路径或生产 JAR。

来源与合并调整见 `SOURCE_MODULES.md`，实际验证范围见 `VERIFICATION.md`。
